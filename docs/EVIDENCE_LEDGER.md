### `mahmoud/boltons` — all eight stages, and an honest non-result

The first complete `hotpath go` against a repository nobody here wrote. Base commit `961dcff3`,
OpenAI `gpt-4.1` planning, Baseten `moonshotai/Kimi-K2.7-Code` writing patches, local execution,
48,291 tokens, ~8 minutes of search.

- Baseline: **519 tests, 3/3 runs green, not flaky, 7.0 s each.**
- Benchmark: **generation failed** (three attempts; the last rejected because only 28% of the
  profiled time was inside boltons' own code), so it fell back to timing the whole test suite —
  5.3 s median at **8.1% noise**, which puts the acceptance bar near 16% of total suite runtime.
- Outcome: **7 candidates, 0 accepted — 2 rejected on correctness, 5 on speed. No pull request**,
  because nothing was proved.

| Verdict | Measured | Hypothesis |
| --- | --- | --- |
| `rejected_correctness` | — | cache the computed length in `IndexedSet.__len__` |
| `rejected_speed` | 0.998x, 95% CI [0.97, 1.07] | avoid redundant index translation in `pop` |
| `rejected_speed` | 1.023x, 95% CI [0.99, 1.03] | inline `_translate_index` |
| `rejected_speed` | 1.046x, 95% CI [0.99, 1.07] | slice assignment in `_balance_list` |

The last row is the whole argument in one line: a change that *looks* 4.6% faster, whose interval
still contains 1.0, and which is therefore not kept. A coarse benchmark did not become a
permissive one — it raised the bar and Hotpath reported nothing rather than something.

**This run is not evidence that boltons cannot be made faster.** It is evidence that no proposed
change cleared a 16% bar on whole-suite runtime. A generated workload over one hot function would
measure a real win that this benchmark cannot see.

### `jaraco/inflect` — two limits that the bundled fixtures could not reach

Benchmark generation succeeded here: it found the hottest project function in the test suite
(`ud_match`, `inflect/__init__.py:2178`, 1.393 s) and wrote a workload over bulk noun
pluralization. Three attempts were all too noisy on this laptop, so the least noisy was kept and
**labelled `(noisy: +/-13%)`** rather than presented as clean — raising the bar instead of
lowering the standard.

The search then returned **12 candidates, 12 `patch_failed`**, every one before a model was
called:

    ValueError: target source exceeds 14000-character budget: inflect/__init__.py

`inflect/__init__.py` is 107,342 characters. The refusal is deliberate — a worker shown a prefix
of a file it must write exact search/replace text against will invent the rest — but `go` never
fitted the budget to the repository, though it already did so for timeouts. Fixed; the budget is
now measured from the editable files, capped at 240,000 characters.

Neither this nor the CRLF defect below was reachable from `demo_repo` or `examples/slow_textstats`,
which are small, LF, and purpose-built. Both made `hotpath go` unusable on ordinary repositories:

- **A CRLF checkout read as a dirty repository.** Git for Windows sets `core.autocrlf=true` in its
  *system* config; Hotpath's git wrapper disables the system config to keep untrusted repository
  config from pointing hooks and filters at arbitrary commands, and that discarded autocrlf too.
  Every file Hotpath rewrote then looked modified, and `ensure_repo` refused the repository.
- **A 14,000-character source budget**, smaller than one ordinary module.
